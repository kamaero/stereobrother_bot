# Техническое задание: Бот для ИИ-обработки и реставрации аудио

## 1. Общее описание

Разработка бота (сервиса) для автоматической обработки, улучшения и мастеринга аудиофайлов с использованием искусственного интеллекта. Основной акцент делается на восстановлении старых/некачественных записей (диктофоны, аудиокассеты) и студийной обработке.

## 2. Монетизация и лимиты пользователя

- **Модель распространения**: Ежемесячная подписка
- **Стоимость**: До 500 рублей в месяц
- **Дневной лимит**: До 100 генераций (попыток обработки) в сутки на одного пользователя
- **Лимит длительности**: Возможность загрузки и обработки файлов длиной до 10 минут

## 3. Функционал: Улучшение качества (Restoration Enhancement)

Бот должен уметь восстанавливать качество звучания, ориентируясь на спецификацию исходников (домашние записи с кассет, диктофонные записи).

### Режимы работы:
- **Улучшение полного микса**: Комплексное улучшение звучания всей композиции (баланс инструментов и голоса)
- **Улучшение отдельных дорожек**: Специализированные алгоритмы для конкретных инструментов:
  - Ударные (Drums)
  - Гитары (Guitars)
  - Бас (Bass)
  - Струнные (Strings)
  - Пианино/Клавишные (Piano)
  - Голос/Вокал (Vocals)

## 4. Функционал: Чистка звука (Denoise)

Инструмент для очистки любых записей от артефактов и посторонних звуков.

### Типы удаляемых шумов:
- Треск
- Шипение (hiss)
- Технический/фоновый шум оборудования

## 5. Функционал: Разделение на дорожки (Stem Separation)

Возможность разложения готового трека на отдельные инструменты (мультитрек).

- **Референс качества**: Как на сайте uvronline.app
- **Конфигурация**: Разделение на 4–6 дорожек (например: Вокал, Бас, Ударные, Мелодия/Другое)

## 6. Функционал: ИИ-Мастеринг (AI Mastering)

Автоматическая финальная обработка трека на основе готовых шаблонов АЧХ (Амплитудно-частотной характеристики). Пользователь выбирает пресет одной кнопкой:

- **Мастеринг подкаста** (акцент на четкость речи)
- **Мастеринг песни** (музыкальный баланс, плотность)
- **Мастеринг рекламы** (громкость, яркость, "радийный" звук)

## 7. Технические требования к файлам

### Входные форматы:
- MP3
- WAV
- M4A
- OGG
- Другие основные аудиоформаты

### Выходные форматы:
Пользователь должен иметь возможность выбрать формат скачивания готового результата:
- **WAV** (без сжатия)
- **MP3** (сжатый формат)

## 8. Архитектурные требования

### 8.1. Технологический стек:
- **Backend**: Python (FastAPI/Flask)
- **AI/ML**: PyTorch/TensorFlow для моделей обработки аудио
- **База данных**: PostgreSQL для хранения пользовательских данных и истории обработки
- **Кеширование**: Redis для управления очередями и временными данными
- **Хранилище файлов**: S3-совместимое хранилище (MinIO или облачное решение)
- **Очереди задач**: Celery + Redis для асинхронной обработки

### 8.2. Модели ИИ:
- **Денойзинг**: Demucs, Spleeter, или специализированные модели для удаления шумов
- **Разделение дорожек**: Demucs, Spleeter, Open-Unmix
- **Улучшение качества**: AudioSuperResolution, SEANet, или кастомные модели
- **Мастеринг**: Нейросетевые модели на основе анализа эталонных треков

### 8.3. API и интеграции:
- **Основной API**: REST API для взаимодействия с фронтендом
- **WebSocket**: Для отслеживания статуса обработки в реальном времени
- **Платежная система**: ЮKassa, CloudPayments или аналоги
- **Уведомления**: Email/Telegram уведомления о завершении обработки

## 9. Безопасность и ограничения

### 9.1. Защита от злоупотреблений:
- Rate limiting по IP и пользователю
- Проверка форматов и размеров файлов
- Анализ контента на предмет запрещенного материала

### 9.2. Конфиденциальность:
- Шифрование файлов при передаче и хранении
- Автоматическое удаление временных файлов
- Политика хранения обработанных файлов (30 дней по умолчанию)

## 10. Масштабируемость

### 10.1. Горизонтальное масштабирование:
